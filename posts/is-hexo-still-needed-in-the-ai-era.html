In the AI era, is the Hexo blogging program still needed?

AI can now write the HTML that a static site generator used to produce. The useful question is not whether Hexo is fashionable, but what a build system is still responsible for.

November 9, 2026 / 6 min read Tooling

A static site generator like Hexo was built to solve a boring problem at scale: turning Markdown files and a theme into a consistent set of HTML pages. For more than a decade it has done that with three commands — generate, serve, deploy. None of that problem disappeared when language models learned to write code.

The question still deserves a straight answer. If an AI can write a post, edit the home page, add the previous and next links, and touch up a template, what is left for Hexo to do? Quite a lot, actually — but not the part most people are arguing about.

What Hexo is actually responsible for

Hexo is not valuable because it writes HTML. It is valuable because it writes it the same way every time. From a post with front matter, it derives the URL, the archive entry, the tag page, the feed, the sitemap, the pagination, and the navigation links. Those pieces are related. Change a permalink rule and the canonical URL, the feed, and every internal link have to change together.

That is a bookkeeping job, and it is the kind of job that grows without anyone noticing. A site with ten posts can survive on hand editing. At a few hundred, the question is not whether the index can be updated by hand. It is whether it will be updated correctly after every publish, on the days when someone is in a hurry.

The other thing a generator provides is a clean boundary: source in, site out. The output directory can be deleted and rebuilt. A deploy becomes a build plus a copy. The source of truth is a set of files you can read, not the last state of somebody’s working directory.

What AI genuinely changes

It lowers the cost of the manual version. This blog is the experiment: no build step, hand-written HTML, and an agent that edits the index and the post navigation. The chores that used to justify a generator — copying a row, incrementing a count, repairing the previous and next chain — are exactly the kind of work an agent can do cheaply, as long as the result is checked.

AI also lowers the cost of making a custom tool. If a generator’s theme system or plugin ecosystem does not fit, an agent can write a small generator tailored to one site in an afternoon. The “I do not want to learn a framework” argument for hand-written HTML gets weaker when the alternative is a tool you ask for and review.

And AI makes content cheap to produce. That cuts both ways: more posts means more indexes, feeds, cross-links, and archive pages to keep coherent. Volume is the condition under which bookkeeping stops being a chore and starts being a source of errors.

What AI does not change

Determinism. A build you can run twice and diff is a check. An agent editing files is an event. Without a build step, the site exists in whatever state the last edits left it. With one, the site is a function of the source. When something looks wrong, the generator gives you a place to look that is not “the last five changes an agent made.”

Reviewability. Generated output is a diff against a pipeline you can inspect. An agent’s ad-hoc edit is also reviewable, but every edit is bespoke: the reasoning lives in a conversation and is not re-run next time. A build system moves that knowledge into a file that outlives the chat.

The publish boundary. A generator is a step that runs at a known time and can fail loudly. That is useful for scheduled publishing, CI checks, and preview deploys. An agent can work inside that boundary too — but then you have built a pipeline, and the agent is not replacing it.

So no, AI does not make Hexo unnecessary in general. It changes who does the maintenance, and it raises the size at which a full generator clearly pays for itself.

The failure mode to avoid

The bad combination is using AI to patch the generated output by hand. Edit the HTML in the output folder and the next build erases the fix. The same mistake appears in reverse when an agent is asked to “just update the live site” without touching the source. In both cases the source and the artifact diverge, and the next person cannot tell which one is real.

The rule is simple: generated files are disposable. If a change matters, it belongs in the post, the theme, or the configuration. An agent is most useful when it works on the source and lets the build do its job.

How to decide now

The test is the same one this blog uses for its own stack. If the site is a handful of pages, published occasionally, with no feed, search, or taxonomy, hand-written HTML with an agent maintaining the links is a legitimate stack. It has fewer moving parts, and the agent absorbs the bookkeeping.

If the archive is growing, more than one person publishes, or the site needs feeds, tags, pagination, or scheduled deploys, use a generator. Hexo remains a good one: actively maintained, fast, and boring in the way that infrastructure should be. If you already run Hexo, the AI era is not a reason to remove it. Keep the build, and let the agent write posts and open pull requests against the source. That is where it adds value without taking over the job the build does better.

The thing to resist is the middle ground: a generator that is bypassed by hand edits, or a hand-maintained site that has grown past the point where hand maintenance is honest. Pick which side owns the bookkeeping, and keep the other side out of it.

The answer

Is Hexo still needed? Where a site has to be rebuilt from a readable source, consistently, yes — and more so as publishing gets faster. What is no longer needed is the assumption that a person must do the maintenance by hand. AI can take the small-site chores, and for a small enough site it can even take the role of the generator. The tool was never the point. The point is having one place that defines the site and one repeatable way to produce it.

A build system is a promise that the site can be rebuilt from a source you can read. AI is useful, but it does not make that promise for you.
